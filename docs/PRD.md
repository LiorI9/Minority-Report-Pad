# Minority Report Pad — PRD (טיוטה חיה)

> מסמך תכנון משותף. נבנה סעיף אחרי סעיף.

## 1. חזון
תוסף לכרום שמאפשר לשלוט בטאב באמצעות מחוות ידיים מול מצלמה, בהשראת הטרקפד של מק.

## 2. תרחיש שימוש מרכזי
מציג שעומד מול קהל ושולט בדפדפן בלי מקלדת ועכבר.

## 3. מודל אינטראקציה (בעבודה)
- **שתי ידיים**
  - **יד ייחוס** — עוגן + מצמד: הסמן מחושב יחסית אליה; מורמת ופתוחה = פעיל, מורדת/אגרוף = מושהה (פותר "מגע מידאס").
  - **יד תנועה** — מזיזה את הסמן ביחס ליד הייחוס.
- **מספר אצבעות ביד התנועה = סוג פעולה**
  | אצבעות | פעולה |
  |---|---|
  | 5 (יד פתוחה) | תזוזה רגילה של הסמן |
  | 1 | לחיצה מסוג א' (TBD) |
  | 2 | לחיצה מסוג ב' (TBD) |
  | 3 | לחיצה מסוג ג' (TBD) |

### סיכונים שזוהו
- **מעברים** בין מספרי אצבעות עוברים דרך מצבי ביניים (5→4→3→2) — צריך ייצוב (debounce).
- **קפיצת סמן** ברגע הלחיצה, כי כיווץ אצבעות מזיז את מרכז היד — לעגן את הסמן לכף היד/שורש כף היד ולהקפיא בזמן מעבר.
- **"מגע מידאס"** — מציג מדבר עם הידיים; צריך מנגנון שמבדיל מחווה מכוונת מתנועה טבעית.
- **עייפות ידיים** ("gorilla arm") — שתי ידיים מורמות לאורך הרצאה.
- **גרירה סינתטית** — גרירה מבוססת עכבר תעבוד; HTML5 Drag & Drop כמעט לא מגיב לאירועים סינתטיים → נפתר ב-0.2 (debugger).
- **מרחק מהמצלמה (סיכון #1)** — מציג על במה עומד ~2–3 מ' ממצלמת הלפטופ (לרוב 720p); היד קטנה בפריים וספירת אצבעות עלולה להיות לא אמינה. → נמדד ראשון ב-Test Bed לפני שינוי מודל המחוות.
- **אמינות זיהוי** — 1 מול 2 אצבעות אמין; 3 מול 4, והאגודל, פחות.

## 4. ארכיטקטורה — הזרקת קלט
- **ברירת מחדל:** סמן וירטואלי (content script) + אירועים סינתטיים ללחיצה/גרירה.
- **פעולות דפדפן דרך API של כרום** (אמין, בלי debugger): החלפת טאב (`chrome.tabs`), קדימה/אחורה, זום (`chrome.tabs.setZoom`), גלילה (`scrollBy`).
- **מצב אמין (`chrome.debugger`)** — נדלק לפי אתר, בבחירה פשוטה של המשתמש (קליק אחד, למשל מהאייקון/פופאפ). ההרשאה `debugger` אופציונלית (`optional_permissions`) ומתבקשת רק בהפעלה הראשונה.
- נימוק: פס האזהרה של debugger גלוי לקהל; רוב הפעולות לא צריכות אותו.

## 5. ארכיטקטורה — מנוע זיהוי
- **Offscreen document (MV3)** מריץ מצלמה + מודל זיהוי ידיים (MediaPipe Hands) — שורד מעבר בין טאבים.
- **תצוגה מקדימה קטנה** (שלד ידיים/מצב מצמד) בפינה — ניתנת להדלקה/כיבוי.
- **הרשאת מצלמה** מאושרת פעם אחת בדף הגדרות של התוסף (offscreen לא יכול להציג בקשת הרשאה).
- זרימה: Offscreen (זיהוי → מחוות) → Service worker (ניתוב, `chrome.tabs`) → Content script (סמן וירטואלי, אירועים).

## 6. סטאק
- **WXT + TypeScript** (מבוסס Vite, MV3).
- entrypoints: `offscreen`, `background` (service worker), `content`, `options` (הגדרות + אישור מצלמה).
- MediaPipe Hands (Tasks Vision) — מודל נטען מקומית מתוך התוסף (MV3 אוסר קוד מרוחק).

## 7. Test Bed — דף בדיקות
דף HTML שמשמש בסיס ניסויים **לפני** התוסף, ודף מטרה לבדיקות **אחרי** שיהיה תוסף.

### תכולה
- **מעבדת מחוות** — מצלמה + שלד ידיים, מצב מצמד, ספירת אצבעות, מחווה מזוהה בזמן אמת, סליידרים לכיול (רגישות, החלקה, debounce).
- **אזורי מטרה** — כפתורים בגדלים שונים, אזור לחיצה ימנית, רשימה גלילה, סליידר, בחירת טקסט, גרירת HTML5.
- **לוג אירועים** — סוג, מטרה, `isTrusted`, latency.
- **תרחישי בדיקה מודרכים** — משימות קצרות עם ציון דיוק וזמן; משמשים גם כמדד הצלחה ל-0.1.

### משימה ראשונה: מדידת מרחק
לפני כל פיתוח אחר — מדידת אמינות ספירת אצבעות (1/2/3/5) ומצב מצמד ב-**1, 2 ו-3 מטר**, במצלמת לפטופ ובפיקסל.
מדדים: אחוז זיהוי נכון, יציבות (ריצוד בין פריימים), FPS, latency.
**סף הצלחה:** 90% זיהוי נכון של מספר האצבעות (אחרי ייצוב) במרחק **1 מטר**. מתחת לסף — משנים את מודל המחוות. 2–3 מ' נמדדים לצורך מידע ורודמפ.
**סטטוס:** עבר באימות ויזואלי (Mac, Pixel, iPhone) — מדידה כמותית נדחתה; נחזור אליה אם יופיעו בעיות זיהוי בשטח.
הנתונים יקבעו אם מודל המחוות נשאר, או שעוברים לחלופה (הגבלת מרחק / חיתוך חכם סביב המציג / מצלמה חיצונית).

### מכשירים
- **דסקטופ (כרום)** — יעד ראשי, לפני ואחרי התוסף.
- **Pixel 7a (כרום לאנדרואיד)** — הדף רספונסיבי ועובד גם בטלפון על סטנד (~מטר). תוספים לא רצים באנדרואיד — בטלפון רק ה-Test Bed.
- דרישה: הגשה ב-**HTTPS** (גישה למצלמה מחייבת secure context). אירוח: **GitHub Pages**, deploy אוטומטי ב-GitHub Actions מכל push ל-main.
- ✅ אומת (גרסה ראשונה): Test Bed עובד ב-Mac, Pixel ו-iPhone (Safari/iOS).
- למדוד: FPS ו-latency של המנוע על ה-Pixel (הערכה: 15–30 FPS).

### מבנה קוד — מנוע משותף (מונוריפו)
- `packages/gesture-engine` — TypeScript טהור, בלי תלות בכרום: landmarks → מצמד/אצבעות/מחוות.
- `apps/testbed` — אפליקציית Vite שמשתמשת במנוע.
- `apps/extension` — תוסף WXT שמשתמש באותו מנוע.

### מנוע מחוות — מימוש (`GestureEngine`)
- קלט: landmarks + יד אמיתית (ימין/שמאל) לכל יד, וזמן. פלט: מצב מצמד, תנוחה מיוצבת, סמן (0..1) ואירועים.
- **תפקידי ידיים** לפי היד הדומיננטית (מוגדרת בכיול).
- **מצמד** עם היסטרזיס: יד ייחוס ≥4 אצבעות = פעיל, ≤1 = מושהה. שחרור מצמד מסיים גרירה.
- **תנוחות**: 4–5 אצבעות = 5 (האגודל לא אמין). תנוחה חדשה מתקבלת אחרי `stableMs` (ברירת מחדל 150ms); הסמן קפוא בזמן מעבר.
- **סמן**: מיקום יד התנועה יחסית ליד הייחוס, מוחלק במסנן One Euro, רגישות מתכווננת.
- **2 אצבעות**: תנועה מעבר ל-deadzone = גלילה טבעית (כמו מק); בלי תנועה = לחיצה ימנית ביציאה מהתנוחה.
- **3 אצבעות**: תנועה אופקית מהירה (≥0.08 תוך 300ms) = החלפת טאב; אחרת = גרירה. זיהוי ההחלקה משתמש במיקום הגולמי (בלי השהיית המסנן).
- **Handedness**: MediaPipe מניח תמונה מראתית; אנחנו מעבירים פריים גולמי, לכן התוויות מוחלפות כברירת מחדל (ניתן לשינוי בכיול).

### ממצאים מה-Test Bed
- אירועים סינתטיים (click, contextmenu, mousedown/up) מגיעים עם `isTrusted: false`, ובכל זאת כפתורים, לחיצה ימנית, סליידר מבוסס pointer וגרירת עכבר עובדים.
- גלילה דרך `scrollBy` מייצרת אירועי `scroll` עם `isTrusted: true` — הגלילה לא צריכה debugger.

## 8. תכולה ורודמפ
### גרסה 0.1 — MVP: כל מיפוי המק
- מצמד (יד ייחוס) + סמן וירטואלי (5 אצבעות)
- 1 אצבע = לחיצה שמאלית
- 2 אצבעות = לחיצה ימנית; החזקה + תנועה = גלילה
- 3 אצבעות = גרירה; החלקה צידית = החלפת טאב
- הזרקה סינתטית + `chrome.tabs` בלבד (ללא debugger)
- Offscreen + תצוגה מקדימה קטנה; דף הגדרות לאישור מצלמה
- **קליברציה בסיסית**: רגישות סמן + בחירת יד דומיננטית (איזו יד היא יד התנועה)

### גרסה 0.2 — טיוטה
- מצב אמין (`chrome.debugger`) לפי אתר

### גרסה 0.3 — טיוטה
- **זום בשתי ידיים** — המרחק בין הידיים שולט בזום (`chrome.tabs.setZoom`).
- **התאמה אישית מלאה** — הדרכה ראשונית, מיפוי מחוות מותאם.

### בהמשך
- לא בתכנון כרגע: קיצורי מצגות ייעודיים, פרסום בחנות.

## 9. החלטות פתוחות

## 10. החלטות שהתקבלו
- בסיס: מחוות ידיים במצלמה, חיקוי טרקפד מק.
- תרחיש: עמידה מול קהל.
- שתי ידיים: יד ייחוס + יד תנועה; 5 אצבעות = תזוזה.
- יד ייחוס = עוגן + מצמד.
- הזרקת קלט היברידית; debugger לפי אתר בבחירה פשוטה.
- זיהוי ב-Offscreen document + תצוגה מקדימה קטנה.
- סטאק: WXT + TypeScript.
- MVP 0.1 = כל מיפוי המק + קליברציה בסיסית, ללא debugger.
- Test Bed לפני התוסף, עם מנוע מחוות משותף (מונוריפו).
- Test Bed רספונסיבי, עובד גם ב-Pixel 7a; מאורח ב-GitHub Pages.
- משימה ראשונה של ה-Test Bed: מדידת אמינות זיהוי במרחקים 1/2/3 מ'; סף הצלחה 90% ב-1 מ'.
- הקוד עובר עכשיו לריפו חדש וייעודי (מונוריפו).
- 0.2 = debugger לפי אתר; 0.3 = זום בשתי ידיים + התאמה אישית מלאה.
- מיפוי אצבעות כמו טרקפד מק (1 = שמאלית, 2 = ימנית/גלילה, 3 = גרירה/טאבים).
- קודם מסמך תכנון, אחר כך ריפו חדש ונפרד.
